# TextChanger

入力テキストを5種類の形式へ同時変換する、オフラインで使える単体HTMLツールです。外部通信・ビルド・実行時の追加依存はありません。

- A5M2用 Caption
- タブ区切り（Excel向け）
- SQL の IN 句
- PostgreSQL `SELECT + INSERT + DELETE`
- 連番調整（テキスト中の数値を一括で増減）

左右1:2の画面で入力と結果を表示し、狭い画面では1列に並びます。画面全体はブラウザの表示領域内に収め、収まりきらない場合はデスクトップでは結果一覧、狭い画面では本文内をスクロールできます。GYOMU-UI 0.6.1に基づく配色・文字サイズ・操作部品の寸法を使用し、タッチ環境の操作領域は44pxを確保しています。CSS・JavaScript・SVGアイコンはHTML内に含まれます。

## 使い方

1. `text-changer.html` をブラウザで開きます。
2. 左の入力欄に、1行に1つずつ値を入力します。
3. 右側5カードに同時表示された結果を確認します。
4. 必要な形式のカード右上「コピー」を押して利用します。

A5M2用 Caption カードの使い方:
- [公式の擬似命令形式](https://www.a5m2.mmatsubara.com/help/SQLEditor/giji.ado.html) に合わせて `--*Captions 列A,列B` を生成します。
- 1つの入力値にカンマがある場合は、意図しない列分割を避けるため、このカードの出力を空にします。他のカードは通常どおり変換します。

PostgreSQL `SELECT + INSERT + DELETE` カードの使い方:
- 1行目をカラム名（ヘッダー）、2行目以降をデータ行にしたタブ区切り表を貼り付けます（Excelのコピー貼り付けを想定）。
- コピーボタン左のテーブル名入力で、生成先テーブルを変更できます（初期値は空欄）。
- テーブル名入力を変更すると、生成結果に即時反映されます。
- テーブル名入力が空欄の場合は、`???` で生成します。
- テーブル名は識別子として検証・引用します。`public.orders`、`"MySchema"."Order"` のような指定に対応し、引用していない英大文字はPostgreSQLの規則に合わせて小文字にします。
- Excel形式の引用セル（セル内改行・タブ・`""` による引用符）に対応します。通常の値の前後の空白は保持し、カラム名の前後の空白は除去します。
- 先頭のBOMは除去します。NULや不正なUnicodeを含む値は、文字を置換してSQLを作ることなく出力を止めます。SQL IN句も同じ文字検査を行います。
- 列数の不一致、空・重複カラム名、不正な引用セル、不正なテーブル名、NUL文字を含む表では、このカードの結果を空にしてコピーを無効にします。不正な行だけを省いてSQLを生成することはありません。識別子は標準的なPostgreSQLの上限（UTF-8で63バイト）以内を対象にします。
- 空行は無視しますが、タブで区切った空セルの行は保持します。1列だけの空セルを明示する場合は `""` と入力します。
- `SELECT` / `DELETE` の `WHERE` 条件では、空欄セル・`NULL` 文字列（大文字小文字無視）・`<< NULL >>`・`< NULL >`・`« NULL »` を条件に含めません（全行で条件が空になる場合は `WHERE 1 = 0` になります）。
- `INSERT` では、`NULL` 文字列（大文字小文字無視）・`<< NULL >>`・`< NULL >`・`« NULL »` は `NULL` として扱い、空欄セルは半角スペース1文字（`' '`）として出力します。
- 事前チェック用の `SELECT` 文を冒頭に出力します（各行の `DELETE` と同じ条件で `SELECT * FROM ...`）。
- `INSERT` と `DELETE` はそれぞれ `BEGIN;` / `COMMIT;` で囲んで生成します。
- `SELECT` / `INSERT` / `DELETE` の文末セミコロンは、単独行（左端）で出力します。
- 同一の検索条件は1つにまとめます。`INSERT` の重複行や件数は変更しません。

連番調整カードの使い方:
- コピーボタン左の増減値入力に整数を入れると、入力テキスト中のすべての数字に対して足し算（負数なら引き算）した結果が出力されます。
- 入力の改行や空行はそのまま保持されます。例えば `No.1` → `No.2` → `No.3` のような連番テキストに対して `5` を入れると `No.6` → `No.7` → `No.8` になります。
- 増減値が空欄または `0` の場合は、入力テキストをそのまま出力します。
- 整数演算は `BigInt` で行うため、16桁以上の番号も丸めずに変換します。増減値は符号付き10進整数だけを受け付け、小数・指数表記・不完全な入力では元のテキストを維持します。
- 対象は従来どおり半角数字の連続部分です。符号・小数点・区切り文字は文字として残り、増減値が0以外の場合、ゼロ埋めは維持しません。
- 大きな増減値は直接入力・貼り付けで指定してください。数値欄の上下ボタン・矢印キーはブラウザ標準の動作で、大きな整数を丸めたり指数表記に変える場合があります。変換処理自体は、数値欄に保持された10進整数を `BigInt` で扱います。

## コピー・テーマ・保存

- 各カードの「コピー」はその結果だけをコピーします。空の結果はコピーできません。成功時だけ「コピーしました」と表示し、読み上げ用の状態にも反映します。
- コピー成功の表示中は、ボタンにマウスを重ねても成功時の配色を維持します。
- コピー前と非同期処理の完了時に入力・出力を照合します。連続操作や入力変更、ページ離脱・非表示による古い処理を抑止し、代替コピーではフォーカス・選択範囲・スクロール位置を復元します。
- ヘッダー左上は文字のみのタイトルです。右上の太陽／月アイコンでライト／ダークを切り替えます。初回はライト、保存済みの設定があればそちらを優先します。
- モード切り替えにマウスを重ねるか、キーボードでフォーカスすると、「テーマ切替」のツールチップを表示します。ツールチップ上へマウスを移しても表示を保ち、`Esc`で閉じられます。
- 入力・テーブル名・増減値・テーマを従来の `textChanger_settings` キーで `localStorage` に保存します。通常は入力停止から500ms後、入力が続く場合も2秒を目安に保存し、ページ離脱・非表示時にも未保存分を反映します。
- 保存時は最新の保存データに、このタブで変更した項目だけを反映します。同じ項目の同時編集は後の保存が優先されます。別タブで削除された入力を、テーマなどの変更だけで保存し直すことはありません。
- 壊れた保存データや想定外の型は無視します。保存禁止・容量不足でも変換は継続しますが、入力復元は保証できません。ファイルを直接開いた場合の保存範囲はブラウザに依存し、OSの強制終了やタイマー抑制中の保存間隔は保証対象外です。
- IMEの変換候補操作中は再計算を控え、確定・フォーカス移動で反映します。ブラウザの補完やページ復帰時も入力を再確認し、不正なテーブル名・増減値は `aria-invalid` に反映します。

SQL IN句のアポストロフィは二重化します。一般的な標準SQL文字列を生成するため、DB固有のバックスラッシュ解釈は実行環境の設定に依存します。PostgreSQLカードでは、[PostgreSQLの字句規則](https://www.postgresql.org/docs/16/sql-syntax-lexical.html) に基づき識別子と文字列を引用し、アポストロフィ・バックスラッシュを保持します。Excel向け出力はタブ・引用符を含む値を引用します。

## 内部構成

- CSSは `reset → base → component → utility` のレイヤーで管理し、色は `oklch`、配色モードはJavaScriptの `colorScheme` で制御します。
- テーマ・状態・画面幅ごとのCSSは関連するセレクター内へネストし、ボタン・入力欄・パネルの派生形は `&.クラス名` でまとめています。メディアクエリーは範囲構文（`width <= ...`）を使い、入力欄のモバイル指定とヘッダー・本文の左右余白を共通化しています。
- SVGのコピー・チェックアイコンはHTML内の `symbol` を `use` で参照します。ボタンと出力・アイコン・状態ラベルの対応は起動時に取得し、入力のたびにDOMを検索しません。
- 起動処理を `_init` にまとめ、入力イベントは親要素で受け取ります。保存データの型検査とSQLセル値の正規化はそれぞれ一か所に集約し、増減値の検証と変換では共通の整数パターンを使います。
- 変更された入力・設定に関係する結果だけを再計算します。テーブル名だけの変更では、直前1件の表の解析・整形結果を再利用します。識別子や表の不正は判明した時点で処理を打ち切ります。
- コピー要求は最新の1件で管理します。ボタンごとのDOM参照・直前の出力・コピー表示のタイマーは1つのMapにまとめ、出力とボタンの状態を同じループで更新します。未保存の設定は別に管理し、不要なDOM更新を避けています。
- Unicodeの検査には `String.prototype.isWellFormed()` を使用します。CSSネスト・範囲メディアクエリー・このAPIに対応したモダンブラウザが対象です。`file://`でClipboard APIを利用できない環境向けの代替コピーは維持しています。

## 検証

Node.js 22以上で実行します。Playwright・対応ブラウザ・PGliteは開発時のみ必要です。

```sh
node --test tests/logic.test.cjs
node --test tests/browser.test.cjs tests/quality-rounds.test.cjs
node --test tests/postgres.test.cjs
```

別の場所に用意した依存ライブラリを使う場合:

```sh
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright node --test tests/browser.test.cjs tests/quality-rounds.test.cjs
PGLITE_MODULE=/path/to/node_modules/@electric-sql/pglite node --test tests/postgres.test.cjs
```

- ロジック: 引用セル・Unicode・識別子・NULL・大整数・不正入力を検証します。
- ブラウザ: Chromium・Firefox・WebKitでHTMLの直接起動、5種類の変換、保存・復元、コピー競合、キーボード操作、IMEイベント、10万行の入力を検証します。外部HTTP通信・コンソールエラー・未処理例外は失敗条件です。クリップボードはテスト用APIに置き換えるかcopyイベントをキャンセルし、OSのクリップボードを書き換えません。
- PostgreSQL: [PGlite](https://pglite.dev/docs/about) 0.5.8のメモリ内DBで、生成したSQLの挿入・照合・削除、対象外の行の保持、文字列や型付きカラムを検証します。既存DBには接続しません。

検証結果・履歴と対象範囲は [QUALITY.md](QUALITY.md) に記録しています。A5M2・Excel実アプリ、OSのIME候補画面、読み上げ音声、個別DBの権限・独自設定は自動テストの対象外です。
