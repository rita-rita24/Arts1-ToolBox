# TextChanger

1行ごとの入力値を、5種類の形式へ同時変換する単体HTMLツールです。

## 業務UI版

- `text-changer.html` に業務UIのスタイルを適用しています。
- 提供された GYOMU-UI 0.6.1 の配色・文字サイズ・操作部品の寸法を使用しています。既存の文言・ボタン数・5種類の変換機能は維持しています。
- コピーボタンは主要ボタン用の青系配色を使用します（ライトは青、ダークは淡い青）。
- コピー対象が空のボタンは無効になり、ホバー時は操作禁止のカーソルを表示します。変換結果が生成されると再び操作できます。
- 連番調整の増減値は左寄せで表示し、入力幅と上下ボタンの手前の余白を確保しています。
- ライト/ダーク切り替えは、ヘッダー右上の太陽／月アイコンで操作します。
- 初回表示はライトモードです。保存済みのテーマ設定がある場合は、その設定を優先します。
- CSSはHTML内の `<style>`、JavaScriptは `<script>`、アイコンはインラインSVGとして内包しています。別のCSS・JS・フォントファイルは不要で、`text-changer.html` 1ファイルだけをコピーしてオフラインで利用できます。
- 狭い画面では1列に並び、タッチ環境の操作領域は44pxを確保します。
- 入力内容・テーマなどの保存キーは従来と同じです。ファイルを直接開いた場合の保存範囲はブラウザに依存します。

## できること

- 画面を左右1:2で表示（両端に少し余白あり）
  - 左: 入力欄のみ
  - 右: 変換結果カード5種を縦に表示
- 入力に応じて、5モードを同時リアルタイム変換
  - A5M2用 Caption 変換
  - タブ区切り変換（Excel向け）
  - SQL の IN 句変換
  - PostgreSQL `SELECT + INSERT + DELETE` 変換
  - 連番調整（テキスト中の数値を一括で増減）
- 各カード右上の「コピー」ボタンで、そのカード結果だけをコピー
- ライト/ダークモードをヘッダー右上のスイッチで切り替え
- 入力内容とテーマ設定を `localStorage` に保存

## 使い方

1. `text-changer.html` をブラウザで開きます。
2. 左の入力欄に、1行に1つずつ値を入力します。
3. 右側5カードに同時表示された結果を確認します。
4. 必要な形式のカード右上「コピー」を押して利用します。

A5M2用 Caption カードの使い方:
- [公式の擬似命令形式](https://www.a5m2.mmatsubara.com/help/SQLEditor/giji.ado.html) に合わせて `--*Captions 列A,列B` を生成します。
- 1つの入力値にカンマがある場合は、意図しない列分割を避けるため、このカードの出力を空にします。他のカードは通常どおり変換します。

PostgreSQL `SELECT + INSERT + DELETE` カードの使い方:
- 1行目をカラム名（ヘッダー）、2行目以降をデータ行にしたタブ区切り表を貼り付けます（Excelのコピー貼り付けを想定）。
- コピーボタン左のテーブル名入力で、生成先テーブルを変更できます（初期値は空欄）。
- テーブル名入力を変更すると、生成結果に即時反映されます。
- テーブル名入力が空欄の場合は、`???` で生成します。
- テーブル名は識別子として検証・引用します。`public.orders`、`"MySchema"."Order"` のような指定に対応し、引用していない英大文字はPostgreSQLの規則に合わせて小文字にします。
- Excel形式の引用セル（セル内改行・タブ・`""` による引用符）に対応します。通常の値の前後の空白は保持し、カラム名の前後の空白は除去します。
- 先頭のBOMは除去します。NULや不正なUnicodeを含む値は、文字を置換してSQLを作ることなく出力を止めます。SQL IN句も同じ文字検査を行います。
- 列数の不一致、空・重複カラム名、不正な引用セル、不正なテーブル名、NUL文字を含む表では、このカードの結果を空にしてコピーを無効にします。不正な行だけを省いてSQLを生成することはありません。識別子は標準的なPostgreSQLの上限（UTF-8で63バイト）以内を対象にします。
- 空行は無視しますが、タブで区切った空セルの行は保持します。1列だけの空セルを明示する場合は `""` と入力します。
- `SELECT` / `DELETE` の `WHERE` 条件では、空欄セル・`NULL` 文字列（大文字小文字無視）・`<< NULL >>`・`< NULL >`・`« NULL »` を条件に含めません（全行で条件が空になる場合は `WHERE 1 = 0` になります）。
- `INSERT` では、`NULL` 文字列（大文字小文字無視）・`<< NULL >>`・`< NULL >`・`« NULL »` は `NULL` として扱い、空欄セルは半角スペース1文字（`' '`）として出力します。
- 事前チェック用の `SELECT` 文を冒頭に出力します（各行の `DELETE` と同じ条件で `SELECT * FROM ...`）。
- `INSERT` と `DELETE` はそれぞれ `BEGIN;` / `COMMIT;` で囲んで生成します。
- `SELECT` / `INSERT` / `DELETE` の文末セミコロンは、単独行（左端）で出力します。
- 同一の検索条件は1つにまとめます。`INSERT` の重複行や件数は変更しません。

連番調整カードの使い方:
- コピーボタン左の増減値入力に整数を入れると、入力テキスト中のすべての数字に対して足し算（負数なら引き算）した結果が出力されます。
- 入力の改行や空行はそのまま保持されます。例えば `No.1` → `No.2` → `No.3` のような連番テキストに対して `5` を入れると `No.6` → `No.7` → `No.8` になります。
- 増減値が空欄または `0` の場合は、入力テキストをそのまま出力します。
- 整数演算は `BigInt` で行うため、16桁以上の番号も丸めずに変換します。増減値は符号付き10進整数だけを受け付け、小数・指数表記・不完全な入力では元のテキストを維持します。
- 対象は従来どおり半角数字の連続部分です。符号・小数点・区切り文字は文字として残り、増減値が0以外の場合、ゼロ埋めは維持しません。
- 大きな増減値は直接入力・貼り付けで指定してください。数値欄の上下ボタン・矢印キーはブラウザ標準の動作で、大きな整数を丸めたり指数表記に変える場合があります。変換処理自体は、数値欄に保持された10進整数を `BigInt` で扱います。

## 内部品質と検証

- UI要素・表示文言・ボタン数・CSSを増やさず、内部ロジックと既存要素のアクセシビリティ属性を改善しています。
- SQL IN句のアポストロフィは二重化します。一般的な標準SQL文字列を出力する機能のため、利用DB固有のバックスラッシュ解釈などは実行環境の設定に依存します。
- PostgreSQLカードでは、アポストロフィとバックスラッシュを保持する文字列を生成します。識別子と文字列の扱いは [PostgreSQLの字句規則](https://www.postgresql.org/docs/16/sql-syntax-lexical.html) に基づきます。
- Excel向けタブ区切り出力は、タブ・引用符を含む値を引用し、セルの分裂を防ぎます。
- コピー完了の表示はコピーAPIの成功時だけ行います。失敗・連続操作・処理中の入力変更を扱い、代替コピーでは元のフォーカスと選択範囲を復元します。
- コピーの新旧判定はカードをまたいで行い、古いコピーの失敗から代替コピーが走って新しい内容を上書きすることを防ぎます。代替コピーではページの文字選択・入力欄の選択範囲・スクロール位置も復元します。
- 代替コピーでは逆方向に選択した文字の開始点・終点も保持します。ページを離れた後に古いコピー処理から代替コピーや成功表示が走ることも防ぎます。
- タブが非表示になった後に遅れて完了したコピーについても、代替処理と成功表示を抑止します。再表示時は、復元された入力・出力・テーマを照合して更新します。
- コピー直前にも最新の入力を確認し、入力イベントが発生しない復元・変更でも古い結果をコピーしないようにしています。
- 出力欄だけがブラウザに復元された場合も、生成結果と照合してからコピーします。入力が同じ場合の不要な再計算は行いません。
- コピーAPIの待機中に入力・テーブル名・増減値がイベントなしで変わった場合も再確認し、古い代替コピーと成功表示を抑止します。
- コピー開始時と完了確認時にも保存を予約します。入力イベントなしで変わった値をコピーした場合、その後ページを離れなくても入力・設定が保存対象になります。
- 既存の「コピーしました」を読み上げ用の状態とボタンの説明に関連付けています。同じラベルを不要に書き直さず、入力のたびに通知が繰り返されることを抑えます。
- 無効なテーブル名・増減値には `aria-invalid` を設定します。文言やエラー表示は追加していません。
- `aria-invalid` は状態が変わるときだけ書き換えます。数値欄で `-` などを入力途中の状態も、ブラウザの `badInput` を確認して反映します。
- スペルチェック・自動大文字化・自動修正を無効にする属性を指定しています。対応するブラウザでは、値や識別子への意図しない入力補正を抑えます。
- 入力の保存待ちがある場合は、ページを離れるときや非表示になるときにも保存します。保存禁止・容量不足では変換を継続しますが、再読み込み後の入力復元は保証できません。ブラウザやOSの強制終了も保存対象外です。
- 通常は入力停止から500ms後に保存し、入力が続く場合も2秒を目安に保存します。ブラウザによるタイマーの抑制中はこの間隔を保証しません。
- 保存時は最新の設定を読み直し、そのタブで編集した項目だけを反映します。別タブの入力を古い内容で巻き戻すケースを防ぎます。同じ項目の同時編集は後に保存した値が優先され、共同編集の履歴管理は行いません。
- 別タブなどで保存項目が削除された場合、テーマなど他の項目の変更によって古い入力を保存し直しません。開いている欄の内容は保持し、その欄を再編集した場合に保存します。
- 壊れた保存データや想定外の型は無視して起動します。既存の保存キーは維持しています。
- 増減値やテーブル名の変更では、影響する変換だけを再計算します。不正なテーブル名の場合は、表の解析に入る前にPostgreSQLの生成を止めます。
- テーブル名だけを変更した場合は、直前の入力から作成したカラム・値・検索条件を再利用し、全行の再解析と値の再整形を省きます。テーブル名は値と分離して組み立てるため、セル内に同じ名前があっても書き換えません。再利用データは直前の入力1件分だけ保持し、不正な表の解析結果も再利用します。
- 長すぎる識別子はUTF-8変換の前に除外し、テーブル名の指定が3階層を超える場合も早期に打ち切ります。63バイトまでの有効な識別子の扱いは維持しています。
- テーブル名は正規表現での読み取り段階にも長さの上限を設け、巨大な引用識別子を貼り付けた場合の走査・作業メモリを抑えます。引用符の二重化、Unicode、階層の区切り前後の空白は引き続き扱います。
- 表の解析中にヘッダーの重複・空欄・不正な識別子や列数の不一致が見つかった場合も、その時点で解析を打ち切ります。有効な行だけを抜き出してSQLを作ることはありません。
- TSVのセルは区切りや引用符までをまとめて取り込み、長いセルを1文字ずつ文字列へ追加する処理を省きます。セル内改行・タブ・引用符・空セルの解釈は維持しています。
- 日本語などのIME入力では変換候補の操作中の再計算を控え、確定時に結果を更新します。保存処理は変換候補の操作中も継続します。
- IMEの処理対象を入力欄ごとに追跡し、他の欄から届いた終了通知を混同しません。終了通知が欠けた場合も、その欄からフォーカスが離れると変換を再開します。
- IMEの開始通知が欠けた場合も、変換候補の入力通知から対象欄を追跡し、確定・フォーカス移動時に結果を更新します。
- IMEの終了通知が欠けても、同じ欄から確定済みの入力通知が届けば、その場で変換と保存を再開します。他の欄の入力通知で候補操作を打ち切らず、遅れて届いた終了通知でも変換を二重実行しません。
- ブラウザの補完などで確定時の `change` イベントだけが届いた場合も、入力・テーブル名・増減値を変換と保存に反映します。通常の `input` と両方が届いても変換を二重実行しません。
- ページ復帰時は、入力だけでなく復元された出力欄・テーマのスイッチも確認し、変換結果と配色を揃えます。入力イベントなしで復元された値も保存対象にします。
- 復帰時に入力や設定が変わっていなければ、変換結果を再利用します。復元された出力の修復と入力欄の選択範囲の保持を両立し、大量入力の不要な再計算を抑えます。
- ボタンの有効・無効状態やコピー済みの状態が変わっていない場合は、同じ属性を繰り返し書き換えません。

node --test tests/browser.test.cjs tests/quality-rounds.test.cjs

- Chromium・Firefox・WebKitで、単体HTMLの直接起動、5種類の変換、保存・復元、複数タブ、ストレージ拒否・容量不足、コピーの成功・失敗・競合、キーボード操作、IMEイベント、10万行の変換を確認します。
- `tests/quality-rounds.test.cjs` は17種類の追加シナリオを3ブラウザで検証します。R10では、入力・設定・コピー・復帰・再読み込みを組み合わせた18回の連続操作を行います。R11～R15では、2万行のSQL再利用、コピー時の保存、IME通知の欠落、不要な属性更新、入力変更による再利用データの破棄を確認します。R16～R17では、終了通知のないIME確定と、200万文字を超える不正なテーブル名からの復旧を確認します。

- テスト用ファイル・Playwright・PGliteは開発時のみ使用します。配布物は引き続き `text-changer.html` 1ファイルで、ビルドや実行時の追加依存はありません。
